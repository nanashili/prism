# Implementation notes

These accumulated notes describe development snapshots before the standalone repository was published. Performance results and acceptance checks are historical, and some feature descriptions have been superseded. Use the [project README](../README.md) for the current product overview, setup, identity and compatibility boundary. References to the reference application describe a development baseline, not code required to build Prism.

The [Rust code and performance review](RUST_REVIEW.md) records the current optimizations, measurements, verification limits, and [per-file review](RUST_FILE_REVIEW.md).

The [performance research roadmap](PERFORMANCE_ROADMAP.md) combines five research reports on faster saved-state restore, durable batch decompilation, incremental reconstruction across languages, and bounded CPU/RAM use. It distinguishes current behavior, measured results and proposed work.

A lean native reverse engineering workbench, rebuilt from Reference using eframe/egui and OpenGL. Chat Markdown uses [egui_commonmark_extended](https://docs.rs/egui_commonmark_extended/0.28.3/egui_commonmark_extended/) for CommonMark, wrapped GitHub-flavored tables, links, lists and code blocks. Its typography options follow saved chat font sizes, line height and paragraph spacing. Optional downloads, math, diagrams and heavy syntax-highlighting features remain disabled. The native desktop UI has no embedded webview or Node runtime. Its default Ghidra provider uses Java Ghidra through REA. The experimental Rust Ghidra route requires an optional Cargo feature and explicit provider selection. External engines and agents start only when requested.

This build recreates the home screen, sidebar, chat composer, themes and analysis workbench. It is usable, but **does not yet provide complete upstream feature or pixel parity**. The table below records the remaining scope explicitly.

The first desktop launch shows a short prism intro: a white beam enters the glass and separates into a spectrum against a solid dark background. It continues automatically after 4.2 seconds, or immediately with **Skip intro** (also keyboard accessible). Completion is saved in `desktop.intro_seen`, independently of setup, so subsequent launches go straight to the normal startup screen. If interface animations are disabled, it continues immediately.

On macOS with `NSGlassEffectView` support, `liquid-glass-rs` 0.1.1 supplies the prism itself. A native glass view sits above the animated rays, masked to the prism silhouette with a separate facet outline. It follows the intro's layout and fade, passes clicks through, and is removed when the intro ends. Liquid Glass is not applied to the window background; the sidebar retains its existing frosted material. The adapter balances the allocation retained by this pinned library version. Older macOS versions and other platforms use the [glass artwork](../resources/splash/README.md) as a fallback, loading its texture only for the intro.

The macOS bundle opts out of automatic security-code AutoFill using Apple's [app-specific setting](https://developer.apple.com/documentation/bundleresources/information-property-list/nsautofillrequirestextcontenttypeforonetimecodeonmac). Prism does not mark any text fields as one-time-code inputs, so code suggestions stay disabled in its editors, chat and settings. This does not change AutoFill settings in other applications or guarantee that macOS never launches its shared AutoFill service.

## Design

The presentation follows the current React source in `app/src`: `Shell.tsx`, the home and chat components, workbench chrome, and Appearance settings. It uses the original SVG icons, agent artwork, system UI font and JetBrains Mono. Sidebar widths, card margins, corner radii, composer controls, suggestion cards, settings rows and light/dark palette values come from those components.

Agent artwork is embedded for the bundled brands, including their dark variants. Other registry logos load in a bounded background worker. macOS app and file icons come from `NSWorkspace`; app bundles retain their original path when their executable is opened. Those icons appear in project lists, the project switcher and workbench header. Android, model and GPU formats use the original format artwork. Other platforms currently use format artwork and a generic binary fallback for native files.

The Home footer follows `home/Sidebar.tsx`; the separate workbench footer follows `workbench/sidebar/Footer.tsx`, including Agents, Playbooks, Exports, Engine and Appearance submenus. Shared anchored menus use the original palette, padding, rounded surfaces and row dimensions. Agent, model, effort, mode, permission, chat and function menus have working actions. Keyboard/typeahead details and some context-menu actions still differ from upstream.

The workbench sidebar follows `workbench/sidebar/{Sections,Resources,Functions}.tsx`: project artwork and format pills, collapsible project chats, saved-work categories, Listing, Reconstruct project, Strings, Imports, Segments, resources and grouped functions. Function filters include all functions, your code, renamed symbols and imports; grouping supports modules and package/file paths, with name/address ordering. Module attribution inferred between matching registration markers is labeled as inferred; unknown ownership stays Unmapped. Counts use available project inventories; unknown counts are left blank. Native imports are read with the existing `object` dependency, including a host-preferred architecture in universal Mach-O files.

Function and resource catalogs are built off the UI thread into temporary SQLite indexes. Each loaded branch holds at most 300 rows, each tree caches at most 17 branches, and visible rows are virtualized. Closing a branch releases its descendants. Resource indexing currently covers regular files in macOS app bundles, skips symlinks and supports bounded text/hex reads, Open in split and copying paths. Whole-file Listing reads five functions per page. Collapsed sections, grouping, filters and sidebar visibility persist per project; current-project chats retain search, pin, archive and rename actions in a bounded list. APK resource trees, specialized resource previews, and the original conditional shader/model/profiling sidebar remain unported.

Project switching retains full streamed SHA-256 verification, using the existing hash library's runtime-detected CPU acceleration. Sidebar group queries use the current project's temporary catalog directly, and its position ordering shares SQLite's row index. A local saved-project comparison reduced large-project appearance from approximately 0.70 to 0.10 seconds and complete loading from 2.26 to 1.51 seconds. No project cache or persistent database migration was added; see [measurements and limits](RUST_REVIEW.md#project-switching-follow-up).

The conversation list follows Codex's compact rows, quiet selection, truncated titles, relative timestamps and hover actions. It shows only the current project's chats, above the project browser on Home. Search, pinning, archiving, restoring, renaming and deletion use SQLite; lists load 50 chats at a time. Selection and drafts for saved chats persist per project. A new chat's unsent draft is retained while its tab stays open, but is not persisted across app restarts.

Binary and conversation headers share `src/ui/tab_strip.rs`: the same 36-pixel rectangular tabs, active top marker, natural title widths, horizontal scrolling, hover close buttons and middle-click close action. Conversations retain up to six tabs with agent artwork, independent drafts and sessions, and busy indicators. Workers start lazily on the first prompt. Switching tabs preserves each conversation; the Keep agents running setting controls cancellation when leaving a chat. Closed workers stop in the background and late events cannot target a replacement tab. Closing the panel preserves its chats. Past Chats has its own project-scoped, chronological search with 50-row pages and a two-click hover delete action. Opening a saved chat selects its existing tab when already open. Archive and delete actions close matching open tabs.

The info button toggles a separate native-code Inspector with address, file offset, segment, initial bytes, callers, callees, colour tags and an automatically saved note. Selection reads run on the analysis worker. Patch opens the selected file offset in the existing hex patch editor; Ask sends a question while retaining the composer draft. Notes and tags use project storage and undo. References retain the provider's completeness limitations. Tensor inspection and moving these tools into bottom panels or editor tabs remain unavailable.

The conversation composer uses the existing Codex-style chips, popup menus and agent controls. Its plus button opens the native picker directly, with no attachment popup or path/URL input. On macOS, the same picker accepts multiple files, images and folders together. The slash palette reuses this attachment action. Windows/Linux use the native file picker; folders can still be dropped onto the composer. Dropping local files or folders onto the composer attaches them; dropping elsewhere keeps the existing project-opening behavior. Removable chips scroll horizontally without a visible scrollbar, long drafts scroll within the text area, and the same single-row controls shorten long model names in narrow panels. Attachment-only messages are supported. Each chat retains its own attachment draft across tabs and restarts, and sent messages retain readable resource links.

Attachments are references to their original locations; Prism does not copy files, recursively scan folders or fetch URLs when attaching them. Each message supports up to 32 references, each with a location of at most 4096 bytes. PNG, JPEG, GIF and WebP images are embedded on the agent worker when the ACP agent advertises image prompt support, within a combined 4 MiB input budget. Larger images, other files, folders, existing URL references and images sent to agents without that capability use ACP resource links. The agent needs access to those locations and appropriate tools to read them. Missing local inputs report an error when sending. Files moved after sending are not archived by Prism. Dragged items without a local file location must first be saved, then selected with the plus button. This follows the [ACP v1 content contract](https://agentclientprotocol.com/protocol/v1/content) and [negotiated prompt capabilities](https://agentclientprotocol.com/protocol/v1/initialization).

Conversation rendering follows the original chat components: bordered user messages, flat Markdown answers, copy actions, a tab header with agent artwork, and collapsible thought/tool activity with timings and expandable payload previews. Activity retains at most 2048 blocks and 256 KiB of string payload per turn, and expanded history displays 32 steps at a time. Bounded subagent previews, plans, context usage and a Codex goal bar share the existing conversation panel. Full child-session navigation, proposals and reconstruction timeline cards remain unavailable. Saved chats open their latest 40 messages within a 2 MiB payload budget. Earlier, Newer and Latest controls browse SQLite history through indexed message IDs, retaining one additional page within the same limits. Browsing history leaves the live messages, draft and agent session intact; sending a prompt returns to the latest messages. Database IDs remain local and are excluded from project JSON. A single saved entry that exceeds the page budget reports an error instead of silently producing an empty conversation. Project-file exports still include only the retained latest messages.

Two workbench panes can retain independent tabs, functions, views, navigation histories and scroll positions. Single-clicking a function opens a reusable italic preview; double-clicking keeps it open. Each pane supports up to 32 tabs, a horizontally scrolling tab strip, close/close-others/close-to-the-right menus, Command-W (Control-W on other platforms), and Control-Tab or Control-Shift-Tab navigation. The divider is draggable. Opening a function uses the focused pane; Open in split selects the other pane. Closing one pane retains the other. Analysis, diff, tool, debugger and build responses carry request IDs so a late response cannot replace another pane's content. Debugger controls and reconstruction setup still share one project session. Inactive analysis tabs release their code, graph and reference data and reload through the existing cache when selected. Outputs from commands with side effects stay in their tab so selecting it cannot repeat a build, debugger action or tool call.

All 14 settings pages use the original page titles, navigation groups, introductions, grouped cards, row spacing, controls, icons and previews. Shared rows handle wrapping, disabled explanations, status pills and inline destructive confirmations. Engine choices and permission presets share a fixed-size, thin-ring radio indicator with a centered selected dot and keyboard-focus outline. Search finds individual rows across pages and filters the navigation. Appearance controls change interface scale, transparency, code font, code size, line spacing, syntax colors, line numbers and graph text size. Display-only changes preserve the current analysis session. Installed system code fonts are offered alongside the bundled font.

Storage uses the same centered 720-point content limit as the other settings pages. Its “This device” overview shows a measured total, segmented usage bar, wrapped category legend, local data folder and Refresh. A bounded background scan reads file metadata only, skips symbolic links and reports partial results. Chat review lists the oldest chats across projects in 50-row pages; archived chats can be restored or individually deleted. Deletion and cache clearing reuse inline confirmations. Projects, chat history, generated files, agents and import backups remain distinct categories; external project files and exports are excluded. Settings content and navigation hide scrollbars while retaining wheel and trackpad scrolling.

macOS uses its native frosted window material; blur intensity is controlled by the OS, so Frost is disabled. Other platforms use a solid sidebar, and transparency has no effect there. Font rasterization, native blur and popup rendering can differ from GPUIX. Font metrics, search presentation, richer conversation cards, context menus and setup workflows still have visual differences from upstream. Settings for unavailable features are disabled with explanations, including automatic updates, notification sounds, telemetry, remembered permissions, separate IDA MCP integration, combined engines, fine-grained Ghidra analysis and GPU recording.

Notifications share one bounded, in-memory center across Home, workbench, settings and setup. Up to three compact cards appear at the bottom right; errors stay until dismissed, while routine confirmations expire after five to ten seconds and pause while hovered, focused or expanded. The bell shows unread counts and the latest 24 notifications, with duplicate counts, project names, copyable details and clear-all. Repeated messages within 30 seconds merge. Each item retains at most 8 KiB of technical details and bounded display text; notification history is not written to disk. Existing Chat settings control file-ready, agent-finished and permission alerts. Permission alerts can reopen the requesting chat without granting permission. Project saves, exports, settings confirmations and failures use the same cards. System notifications and sounds remain unavailable. Saved-chat loading continues to treat NULL message text as empty, preserving activity-only messages.

The macOS material is attached to the native container behind the OpenGL content view. Adding it inside the content view covers the rendered UI and produces a blank gray window. The adapter uses pinned `objc2-app-kit` and `raw-window-handle` dependencies already present in the rendering dependency graph.

VSync remains enabled during resizing. Rendering remains event driven, without a continuous redraw timer. The Metal comparison was reverted because its resize improvements did not justify the storage and memory tradeoffs. Measurements and verification limits are recorded in the Rust review above; the original manual resize sluggishness remains unresolved.

## Focused workspaces and optional skills

First-run setup asks what you plan to reverse engineer: binaries, firmware,
web apps, mobile apps, networks, graphics/models, or games. Gaming has separate
choices for engines/assets, runtime/memory, and security research. Change these
choices in **Settings > Workspace**. They filter setup tools, Home suggestions,
skill pickers, and optional debugger, reconstruction and GPU controls. Existing
settings keep all categories enabled. Opening files and explicitly requesting
views remain available. Web and protocol research currently use your agent and
skills; these choices do not add a browser or packet capture engine.

In **Settings > Skills**, paste a public `https://github.com/owner/repository`
URL and choose **Download from GitHub**, or import a local repository/skills
folder. The suggested [mcp-gamehacking library](https://github.com/1llu50ry/mcp-gamehacking)
is optional. Nothing from it is bundled or fetched during setup. Git is required
for downloads. Prism uses a shallow, partial clone and sparse checkout to fetch
`SKILL.md`, license and notice files, then removes Git's object database. The
completed download lives in the app's data folder under `skill-libraries`, with
its repository URL and exact commit recorded. Failed downloads are not added
to Settings. Downloads can be removed; disconnecting a local folder leaves its
files in place. Remove and download again to fetch a newer revision.

Libraries are indexed in the background and searched through a scrolling skill
browser. Topic metadata and names suggest categories; uncategorized skills use
the library's editable fallback categories. Archived-project summaries are
excluded from pickers until enabled for that library. Full `source.txt` archives,
MCP servers, scripts and other supporting files are not downloaded or executed.
Use a local checkout when you need those supporting files. Full skill instructions
are read when invoked, with a 128 KiB limit and visible errors instead of silent
truncation. Invalid or oversized skills are skipped and reported in Settings;
valid skills in the same library remain usable. Indexing supports up to 10,000 skills per library. Refresh the skill
browser after adding files to a local folder.

## Historical run instructions

On this Mac, open `build/Prism.app`. The bundle is ad-hoc signed for local use and is not notarized for distribution.

```sh
cd /path/to/prism
cargo run --release --locked
cargo run --release --locked -- /absolute/path/to/file
```

The repository pins Rust 1.93.1 and exact direct dependency versions. Java Ghidra through REA is the default desktop provider. Build its macOS bundle with:

```sh
python3 scripts/bundle-macos.py
```

Configure external REA, Node, Java and Ghidra in Settings > Engines.
`--java-ghidra` explicitly selects the same default. Rust Ghidra through REA
remains experimental and opt-in. To package its runtime, provide a built REA
package, the Node version pinned by its `.nvmrc`, its Rust worker and the
worker's license notices:

```sh
python3 scripts/bundle-macos.py --rea-rust-ghidra \
  --rea-package /absolute/release/rea \
  --node-runtime /absolute/release/node \
  --rust-ghidra-worker /absolute/release/rea-ghidra-rust-worker \
  --worker-notices /absolute/release/rust-worker-notices
```

For a source build that includes the optional Rust route alongside Java, use
`cargo build --release --locked --features rea-rust-ghidra --bin prism`, then
select **Ghidra (Rust through REA)** in Settings > Engines. The recorded
[benchmarks](REA_RUST_BENCHMARK_20261020.md) do not justify making Rust the
default; see [setup and limits](REA_RUST_PROVIDER.md).

An optional `--matlab-loader` flag packages the desktop executable as
`MATLAB-Prism`, requesting Apple's private MATLAB weak-symbol lookup behavior.
The bundle name, icon and identifier remain Prism, and a `prism` symlink preserves
existing command paths. Native workers launched through `current_exe` reuse the
renamed executable; the separate MCP helper keeps its name. This is disabled by
default: 80 paired warm starts on this Mac measured 8.44 ms normally and 9.78 ms
with the prefix, about 16% slower. These are executable/idle-worker timings,
not time to a ready window. To build a separate opt-in bundle:

```sh
python3 scripts/bundle-macos.py --matlab-loader --output build/matlab-loader/Prism.app
```

The behavior is an undocumented OS implementation detail and may change. See the
[source and measurement details](RUST_REVIEW.md#optional-macos-loader-mode).

The script includes licenses, verifies its signature, and replaces only a bundle bearing this application's identifier. `--skip-build` reuses release executables only when a matching build receipt verifies their provider and hashes. `--output` chooses another destination. The app bundler currently targets macOS; Linux and Windows packaging have not been verified here.

## Resource choices

- Default desktop builds use Java Ghidra through REA with `prism-ghidra-rea`. The optional `rea-rust-ghidra` Cargo feature enables the experimental Rust route. A Rust macOS bundle requires explicit `--rea-rust-ghidra` selection, its REA package, portable Node runtime, worker executable and license notices, and includes those verified inputs.
- The packaged standalone MCP executable is 445,744 bytes (about 435 KiB). After initialization and a window call, an earlier idle helper measured 2,256 KiB resident memory and 0.0% CPU in a `ps` sample on this Mac. Its linked libraries are libSystem and libiconv; it does not load the GUI frameworks. These are observations, not fixed resource limits.
- A fresh release home screen measured about 141 MiB resident memory and 0.0% CPU in an idle `ps` sample on this Mac at a 1440 × 940 window size. This is an observation, not a guaranteed limit or a cross-platform benchmark. Screenshot capture temporarily allocates a full-resolution image.
- Rendering wakes on input or worker events. There is no continuous application repaint timer.
- One analysis worker processes a bounded queue. Function inventories are stored in SQLite and displayed in pages of 300 using virtualized lists. Native inventory imports commit in batches within a transaction.
- Ghidra providers prepare their REA session for the selected project and keep it available for later saved-inventory batches. Switching targets, cancelling or failing an analysis releases the analysis process group. Rizin unloads after 60 seconds without worker requests; ACP sessions unload after ten minutes without prompts.
- REA supervises the optional Rust worker with a sampled RSS termination threshold and per-request timeout; sampling can overshoot and is not an OS-enforced cap. The default Java provider receives its configured heap and analysis-thread settings through REA. Rizin uses its configured process memory and request-time budgets. `jadx` receives a heap setting, which does not cap its entire process. Engine and agent memory is additional to the desktop's memory.
- Code views use a compressed SQLite LRU cache, defaulting to 256 MiB of compressed payloads. SQLite page/index overhead is additional. Hashing, project compression and patched output use streaming buffers rather than loading entire binaries into RAM.
- Extracted project binaries and completed Android output share a separate 1 GiB budget. Old entries are evicted when space is needed; open input paths are retained. Project reopening reuses a cached binary after verifying its hash. Recent projects retain the saved document path so evicted binaries can be extracted again. Android output is checked after jadx finishes, so temporary generation can exceed the budget. Lowering this setting takes effect on the next cache reservation.
- Reference lists retain at most 1,000 incoming and 1,000 outgoing entries, and report truncation. Most displayed content is capped at 1 MiB; protocol frames, archive metadata and queues have separate bounds. Chat retains its recent live messages and, only while browsing history, one additional page of up to 40 messages and 2 MiB of stored payload. Earlier pages are released when replaced or when returning to Latest; all other messages remain in SQLite. Decoded structures and rendering allocations are additional to that payload budget.
- Native file icons use an LRU of at most 64 textures at 64 × 64 pixels, roughly 1 MiB of pixel data. Registry icons are limited to the first 128 entries, 128 KiB per SVG download and 64 × 64 pixels per texture. The registry JSON is limited to 2 MiB and refreshed at most daily. Opening a menu initiates this work; startup does not fetch the registry.
- All-pseudocode export reads 300-row inventory pages and writes each function incrementally. Failed functions are identified in the output; cancellation or file errors preserve the previous completed export through atomic replacement. Objective-C inventory export requires a supporting REA provider.

These budgets do **not** limit saved documents, project/chat history, reconstruction directories, interrupted temporary output or caches owned by external tools, including npm. Agent binary downloads are limited to 512 MiB each, but expanded installations and old agent versions have no global quota. Those can grow on disk. There is no global storage quota or history retention policy. Reanalyze an Android project if its generated sources were evicted.

## Tools and settings

Java Ghidra through REA is the default desktop provider, enabled by `prism-ghidra-rea`. Rust Ghidra through REA requires the optional `rea-rust-ghidra` feature and explicit selection in Settings > Engines. Existing settings migrate unavailable provider IDs to the platform's default. Settings accepts executable paths for REA, its launcher and Rust worker, `jadx`, an ACP agent and LLDB DAP, along with Java Ghidra's runtime and analysis controls when that provider is enabled. Settings also saves startup, chat context, send keys, agent idle behavior, first code view, address formatting, skills and export preferences. Keyboard settings lists the original 46 commands with six keymap presets, key recording, conflict handling, reset and Reference JSON import; commands missing from the Rust workbench remain visible with explanations. Presets cover the supported command subset; importing other tools’ native shortcut formats is not implemented. Existing executables are discovered on the augmented PATH; macOS also checks the installed Reference Rizin and Xcode LLDB locations. No engine is downloaded automatically.

The experimental Rust provider runs REA's Rust Ghidra integration and sends bounded decompilation batches drawn only from Prism's saved analysis inventory. Its separate native worker uses the pinned [`ghidra-decompiler`](https://github.com/koute/ghidra-decompiler/tree/268c3a406d8d964bc00ae2ead4d3e1e1373aaa27) library. It is not the Java Ghidra application or a port of its full project service. Java Ghidra remains the default; provider identities stay separate in settings and the cache.

Opening a native target prepares the selected REA Ghidra provider and reuses the saved Prism inventory. Decompilation is limited to the selected indexed addresses and does not trigger function discovery. Initial analysis and inventory coverage depend on the selected REA provider; unindexed functions remain unknown until a separately requested analysis updates the saved inventory.

Opening a native app, binary or Android package automatically indexes it when that binary hash has no saved function inventory or completed analysis. Existing and imported inventories are reused. Successful indexing records completion in the same SQLite transaction as its functions, including empty inventories; failed and cancelled imports roll back. Analyze remains available for an explicit refresh. Source, model and GPU files retain their existing readers.

Active analysis appears in the bottom status bar with its current stage, a slim progress bar and Stop control. Opening a file starts this indicator before releasing the previous engine and inspecting the new input, including when opening from Home; it then follows the existing analysis stages. REA progress messages and saved-inventory batch counts are reflected as they arrive; providers without numeric progress use an indeterminate bar. The bar also remains available on Home and Settings while analysis runs, and clears on success, cancellation or failure. The MCP window state includes the current analysis stage and counts.

The default Java provider requires configured REA, Node.js, Java and Ghidra installations. The optional Rust provider requires a compatible REA package, Node.js and its separately built worker; the opt-in Rust macOS bundle carries these inputs. Prism's standalone MCP helper can start without an open window, but prepared Ghidra operations require an opened project session. Tool arguments are validated against published schemas. Decompilation requests use bounded batches of saved addresses; a cache miss for an individual function is sent as a one-address batch and retained only after validation. No per-function call path may expand the saved inventory.

The Rust provider is REA's Rust decompiler-library integration, not the complete Java Ghidra project service. Its supported formats, language modules and analysis behaviors follow the pinned worker dependency and REA adapter. Java Ghidra remains available for workflows that require its broader project service. Provider limits and failures remain visible; neither backend claims complete recovery of every function or indirect reference.

Rizin remains directly selectable because REA 6.5.0 does not expose it as a native analysis provider. Its adapter indexes with initial `aa` analysis and exposes a small command whitelist. Pseudocode requires a compatible Rizin decompiler plugin; a missing plugin is reported explicitly. REA supplies optional IDA and Hopper integrations, subject to their own installations and requirements. Android uses jadx directly.

AI chat uses an **ACP adapter**; a plain `codex` command is not an ACP server. The Codex preset finds a local `codex-acp` or uses `npx --yes @agentclientprotocol/codex-acp`, which requires Node/npm and can download its external package on first use. Other presets or a custom executable can be selected. Authentication belongs to the agent. Prism supplies its Rust MCP servers to ACP agents automatically. The Prism and Analysis tools toggles work independently; changing either recreates the agent session on its next prompt.

Agents settings accepts one additional stdio MCP command under Add a tool server. Quoted paths and arguments are supported; the executable starts directly without a shell. Editing keeps a draft until Add is chosen. Invalid quotes leave the saved command unchanged. Clear the field and choose Add to remove it. A saved change recreates the agent session on the next prompt. Agent adapters may also start MCP servers from their own global configuration; those external processes have their own resource costs and are outside Prism's process budgets.

### Rust MCP server

`prism-mcp` is a separate Rust stdio executable included beside the desktop executable in `build/Prism.app/Contents/MacOS/`. It uses the open window's authenticated loopback bridge and existing analysis worker. It starts no window, JavaScript runtime or second analysis engine. No new dependency was added: the helper uses `serde_json`, `dirs` and the standard library. It can be built without desktop dependencies:

```sh
cargo build --release --locked --no-default-features --bin prism-mcp
build/Prism.app/Contents/MacOS/prism-mcp
```

The default mode exposes all 18 implemented tools. `--window` exposes 14 window tools; `--analysis` exposes four analysis tools. `prism mcp` remains supported, as do `prism --prism-mcp` and `prism --rea-mcp`. The app prefers the sibling helper and falls back to `prism mcp` during development when the helper has not been built. For an external MCP client, use this configuration with Prism open:

```json
{
  "mcpServers": {
    "prism": {
      "command": "/path/to/prism/build/Prism.app/Contents/MacOS/prism-mcp",
      "args": []
    }
  }
}
```

`ask_agent` queues a prompt; `get_state` exposes bounded progress, reply text and pane selections. `open_function` accepts either `function` (an original name, local name or address) or `address`, an optional initial `view`, and `split: true` for the other pane. Names must be unambiguous and require an indexed file. `current_view` reads the selection. `rename_function`, `add_note`, `bookmark` and `list_marks` operate on saved local project annotations; empty note text removes the note. `show_screen` navigates to Home, Workbench, Settings or Setup; an optional Settings `page` uses the visible page title.

Analysis tools are `list_functions`, `read_bytes`, `analysis_tools`, `analysis_call` and `decompile_batch`. Always use bounded batches for decompilation and follow `next_offset`; reconstruction generations use `reconstruction_evidence`. Ghidra requests route through the selected REA provider. Prism sends only saved indexed addresses to `decompile_batch`; tools cannot expand that selection or start one-call-per-function pseudocode work. Known backend file-switch and annotation tools are filtered and rejected so they cannot bypass Prism's project state and undo history. This is not a general sandbox for an external analysis provider. Rizin uses the existing Rust adapter; optional IDA and Hopper integrations require REA. Upstream managed, GPU, patch-proposal and type/number-format MCP tools remain outside this adapter. Prism owns a separate persistent `reconstruction_*` workflow; see [generational reconstruction](RECONSTRUCTION.md).

The transport uses bounded UTF-8 JSON lines, negotiated protocol versions and JSON-RPC errors, following the MCP [stdio transport](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports) and [tool result](https://modelcontextprotocol.io/specification/2025-11-25/server/tools) contracts. Tool schemas declare required arguments and reject unknown fields, invalid types and out-of-range byte reads. Initialization and tool discovery work without an open window; execution returns an actionable error when the window is unavailable. The private endpoint is read again for each call, so the helper can reconnect after the app restarts. Tokens are excluded from generated command lines and client configuration. Requests/replies are limited to 8 MiB, one call runs at a time, and idle helpers block on stdin. There is no background polling, retained binary cache or asynchronous runtime. Active calls have a bounded window timeout; mid-call cancellation is not implemented.

Ghidra UI views and MCP requests use Prism's compressed disk cache with a provider-specific identity, address and view. Cache accounting is incremental, eviction uses an access index, and reads update recency at most once per minute. Verified batch pseudocode is retained for later reads; cache misses go through the selected prepared provider. Reanalysis does not broaden a decompilation batch beyond the saved inventory.

The provider list inside the combined model selector shows detected local agents and the configured custom command, grouped by provider with their advertised models. Anthropic and ChatGPT have separate headings. Settings controls which agents appear; the complete platform-compatible ACP registry remains available there for setup. Model lists are cached in a bounded file, loaded at startup before registry refreshes and icons, and refreshed from connected sessions. The shared composer uses cached models immediately. ## Code layout

There is one package with a desktop binary, a standalone MCP binary and a small shared library. `mcp/` owns the stdio protocol, tool schemas, validation and endpoint discovery; it has no dependency on UI or analysis implementation. `ui/` owns presentation, `worker/` coordinates blocking tasks, `analysis/` adapts existing tools, `agent/` speaks ACP, `bridge/` routes authenticated local calls, `protocol/` owns bounded subprocess transport, `storage/` owns SQLite and atomic writes, and `project/` owns archives and patch exports. `debug/` and `reconstruction/` contain their focused workflows.

Communication uses bounded standard-library channels and dedicated blocking workers. Original source files remain outside this directory and have not been replaced by this rebuild.

`url` is a pinned direct dependency already present through the window integration. It creates correctly escaped file URLs for the exports-folder action. The icon adapter reuses the pinned AppKit bindings; the new menus and policies introduce no additional runtime or UI framework.
